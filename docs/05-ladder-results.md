# 이슈 비서 키우기 (L1~L6) 결과

실행: 2026-10-28. 모델: OpenRouter `anthropic/claude-opus-5.5`. 11개 후보 × 6단계, 본 실행은 단계마다 1회다.
본 실행 66회의 비용은 $5.72, 개발 중 시험 실행을 포함하면 약 $12다. 원자료는 [summary-ladder-final.md](../results/summary-ladder-final.md)와 `results/runs/l*-*`에 있다.

## 결론

- **66회 모두 성공했다.** 11개 모두 여섯 기능을 다 만들 수 있었다. 차이는 기능 하나를 더할 때 코드가 **얼마나, 어떤 방식으로** 늘어나는가에서 났다.
- **스킬**: 기본 기능이 있는 8개는 3~6줄을 더하면 됐다. 기능이 없는 LangGraph, Pydantic AI, OpenAI Agents SDK는 스킬 목록과 `load_skill` 도구를 직접 만드느라 15줄이 들었다.
- **메모리**가 가장 크게 갈렸다. 하네스는 작업 폴더의 지침 파일(CLAUDE.md, AGENTS.md)을 기억 장소로 써서 4~9줄이면 됐다. 프레임워크는 장기 저장소를 제공하는지에 따라 7줄(CrewAI)에서 18줄(LangGraph)까지 차이가 났다. CrewAI는 코드는 짧았지만 저장할 내용을 LLM으로 분석하느라 LLM 호출 45번, $0.44가 들었다. 다른 후보는 7~10번, $0.09~0.21이었다.
- **멀티에이전트 구조**는 통제 방식이 둘로 나뉜다. 프레임워크는 그래프, 워크플로, 크루로 순서와 반려 루프를 코드로 고정한다. 하네스(Claude Agent SDK, Deep Agents, Flue)는 서브에이전트를 정의하고 순서는 지시문으로 모델에게 맡긴다. 결과는 같았지만 비용이 달랐다. 하네스 쪽은 $0.20~0.41이었고, 코드로 구조를 고정한 8개(프레임워크 7개와 Pi)는 $0.09~0.23이었다. 호출 수는 7~12번으로 비슷했고, 차이는 주로 호출당 입력 토큰(약 2~5K 대 3~14K)에서 났다. 또 하네스 쪽은 순서를 코드로 강제하지 않으므로 흐름이 모델 판단에 달려 있다.

## 단계와 과제

| 단계 | 더하는 기능 | 과제 | 채점 |
| --- | --- | --- | --- |
| L1 | 기본 호출 | 현장 보고 한 건의 공종과 심각도 판단 | `공종=electrical, 심각도=critical` |
| L2 | 도구 | 3층 전기 미해결 이슈 조사 | 최우선 ISS-014, 담당자 이서연 |
| L3 | 스킬 | 사내 규칙에 맞는 주간 리포트. 규칙은 프롬프트에 없고 SKILL.md에만 있다 | 첫 줄, 건수, 최우선, 담당, 문서번호 `WR-3F-EL` |
| L4 | 서브에이전트 | L3 + 공정 지연 현황. 공정 도구는 서브에이전트(공정 분석가)만 갖는다 | L3 + `지연 공종: 전기 15%p, 설비 12%p`, 에이전트 2개 이상 참여 |
| L5 | 메모리 | 세션 1에서 선호를 기억시키고, 새 대화인 세션 2에서 리포트 요청 | L4 + 마지막 줄 위 `검토 요청: 김현장 소장` |
| L6 | 멀티에이전트 구조 | L4와 같은 리포트를 분석가 → 작성자 → 검토자 팀이 만든다(반려 시 최대 2번 수정) | L4 + 에이전트 3개 이상 참여 |

각 단계 코드는 이전 단계 파일을 복사해 기능만 더했다. L5와 L6는 둘 다 L4 위에 얹었다. 코드: `frameworks/<후보>/l1~l6.*`, `harnesses/<후보>/l1~l6.*`.

| 후보 | L3 스킬 | L4 서브에이전트 | L5 메모리 | L6 멀티에이전트 구조 |
| --- | --- | --- | --- | --- |

| Pydantic AI | △ 직접 | ◐ 도구 안에서 하위 에이전트 실행 | △ 파일로 직접 | △ 코드로 작성 (`pydantic-graph`가 함께 설치되고 Agent 루프의 기반이지만 이번 구현에서는 쓰지 않음) |

| Deep Agents | ✓ `skills` | ✓ `subagents` | ✓ `memory` (AGENTS.md) | ◐ 서브에이전트 + 지시문 |
| Pi (TS) | ✓ `additionalSkillPaths` | △ 세션을 새로 띄우는 도구 | △ AGENTS.md 컨텍스트 파일 활용 | △ 코드로 세션 연결 |
| Flue (TS) | ✓ `useSkill` | ✓ `useSubagent` | △ AGENTS.md (샌드박스 필요) | ◐ 서브에이전트 + 지시문 |

¹ OpenAI Agents SDK의 스킬은 `SandboxAgent`의 `Skills` 기능이다(스킬 파일을 샌드박스에 두고 셸로 읽는 Codex 방식). 세 번 시도했지만 이 실험 환경(OpenRouter Chat Completions)에서는 동작하지 않았다. 첫째, `Filesystem` 기능에 Responses API 전용 도구(`apply_patch`)가 들어 있어 요청이 거부됐다. 둘째, Docker 샌드박스와 `Shell`을 켜도 스킬 파일이 샌드박스에 들어가지 않았다(호스트 경로 허가 설정이 필요한 것으로 보이나 확인하지 못했다).
² `Sessions`는 같은 대화의 기록용이다. 대화를 넘는 `Memory` 기능도 샌드박스 에이전트 쪽에 있다.
³ 서브에이전트 정의가 JSON으로 CLI에 넘어가므로 SDK 내장 MCP 서버를 서브에이전트에만 붙일 수 없다. 메인 에이전트도 그 도구를 보게 되고, `disallowed_tools`로 막으면 서브에이전트도 막힌다.

## 단계별 관찰

- **L1 기본 호출**: 프레임워크는 7~10줄, $0.002다. 하네스는 같은 질문 하나에 Claude Agent SDK $0.035, Deep Agents $0.021, Pi $0.008이 들었다. 기본 시스템 프롬프트와 도구 정의를 싣기 때문이다. ADK는 Runner와 Session 준비 때문에 19줄이었다.
- **L2 도구**: Python 프레임워크는 함수를 그대로 넘기거나 데코레이터로 감싸면 된다(+3~5줄). 하네스와 Mastra는 도구 스키마를 직접 선언해야 한다.
- **L3 스킬**: 기본 기능이 있으면 경로 하나를 넘기면 됐다. CrewAI, Strands, ADK, Mastra, Deep Agents, Pi, Flue가 그렇고, Claude Agent SDK는 프로젝트 스킬 폴더에 두고 설정 소스를 켠다. 우회 구현은 progressive disclosure를 직접 만든다. 스킬 목록은 지시문에 넣고, 본문은 `load_skill` 도구로 필요할 때 불러온다.
- **L4 서브에이전트**: 대부분 하위 에이전트를 도구로 노출하는 같은 모양이다. Pi만 기능이 없어 세션을 새로 띄우는 도구를 직접 만들었다(+24줄).
- **L5 메모리**: 기억하는 방식이 세 가지로 나뉘었다.
  - **파일 기반**: 하네스 4개와, 메모리 기능이 없는 Strands, OpenAI Agents SDK, Pydantic AI가 이 방식이다.
  - **키-값 저장소**: LangGraph(`SqliteStore`), ADK(`SqliteMemoryService`), Mastra(작업 메모리)가 이 방식이다.
  - **LLM 분석과 임베딩**: CrewAI가 이 방식이다.

  모든 경우 세션 2의 프롬프트에는 선호가 없었고, 저장된 기억(CLAUDE.md, AGENTS.md, memories.json, DB)을 거쳐 반영됐다.
- **L6 멀티에이전트 구조**: 순서와 루프를 코드로 고정한 후보는 호출 수가 7~11번이었고, 상한이 코드로 정해진다. 지시문으로 맡긴 하네스는 Claude Agent SDK $0.41, Deep Agents $0.28, Flue $0.20으로, 같은 일을 코드로 짠 Pi($0.09)보다 비쌌다.

| Flue | SKILL.md를 `/`로 시작하는 경로로 import하면 프로젝트 루트 기준으로 해석 | 상대 경로로 import |

| Pi | 서브에이전트와 메모리 기능이 없음 | 세션을 띄우는 도구, AGENTS.md 활용 |

채점기 수정도 밝혀 둔다. 둘 다 내 채점기의 문제였고, 고친 뒤 해당 단계 실행을 모두 다시 채점했다.
- L2는 정규식이 답 전체의 끝에 고정돼 있어 설명이 붙은 답을 떨어뜨렸다.
- L3는 리포트 앞뒤의 설명까지 리포트로 봤다. 리포트 블록(`[주간 리포트]`부터 `문서번호:`까지)만 검사하도록 고쳤다.

## 발표에 쓸 만한 그림

1. **"기능 하나 더하는 비용" 히트맵**: 행은 후보, 열은 L2~L6, 칸은 추가 줄 수다. 기본 지원(짧음)과 우회(김)가 색으로 드러난다.
2. **메모리 방식 3분류 그림**: 파일 / 키-값 저장소 / LLM 분석+임베딩과, CrewAI의 45번 호출 대비.
3. **L6 통제 방식 대비**: 코드로 고정한 구조(그래프·워크플로)와 지시문으로 맡긴 구조(하네스)의 비용·호출 수.

## 한계

- 단계마다 1회만 실행했다. 동작 확인과 코드 비교가 목적이고, 성능 통계로 쓰면 안 된다.
- 코드 줄 수는 같은 과제를 각 후보의 관용적 방식으로 짠 한 가지 구현의 값이다. 더 짧게 쓰는 방법이 있을 수 있다.
- L6의 하네스는 순서를 지시문으로 맡겼다. 하네스도 코드로 세션을 이어 붙이면(Pi처럼) 구조를 고정할 수 있다.
- OpenAI Agents SDK의 스킬과 메모리는 이 실험 환경(OpenRouter Chat Completions)의 제약 때문에 기본 기능으로 평가하지 못했다.
