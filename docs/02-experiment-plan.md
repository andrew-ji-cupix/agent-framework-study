# 실험 설계: Framework 트랙과 Harness 트랙

작성: 2026-10-28. 상태: 단계 1 완료 ([결과](03-phase1-results.md)), 단계 2 중 F2·F3 완료 ([결과](04-f2-f3-results.md)), H2·H3 대기.
추가 실험: 이슈 비서 키우기 L1~L6 완료 ([결과](05-ladder-results.md)).
LLM: OpenRouter `anthropic/claude-opus-5.5` (입력 $4, 출력 $20, 캐시 읽기 $0.20 per MTok).

## 1. 답하려는 질문

- **Framework 트랙**: 같은 기능을 만들 때 프레임워크마다 코드량, 개념, 토큰 오버헤드가 얼마나 다른가? 2026년 공통 기본기(구조화 출력, 멀티에이전트, 사람 승인 후 재개)를 실제로 어떻게 지원하는가?
- **Harness 트랙**: 완성된 에이전트 루프에 같은 과제를 맡기면 성공률, 비용, 시간이 어떻게 다른가? 우리 도구와 규칙, 권한 제한을 얹기는 얼마나 쉬운가?

## 2. 비교 대상

| 트랙 | 후보 | 언어 |
| --- | --- | --- |
| Framework | LangGraph, CrewAI, Strands Agents, Google ADK, OpenAI Agents SDK, Pydantic AI | Python |
| Framework | Mastra | TypeScript |
| Harness | Claude Agent SDK, Deep Agents | Python |
| Harness | Pi, Flue (Pi 기반 프레임워크) | TypeScript |

실행 시점의 최신 안정 버전을 lock 파일로 고정하고, 결과표에 버전을 함께 적는다.

## 3. 공정성 조건

- 모든 후보가 같은 모델(`anthropic/claude-opus-5.5`)을 OpenRouter로 호출한다. 후보마다 문서화된 연동 방식(OpenAI 호환 또는 Anthropic 호환 엔드포인트)을 쓰고, 어느 쪽을 썼는지 기록한다.
- 프롬프트, mock 데이터, 도구 동작이 같다. 도구는 Python 구현 1벌과 TypeScript 포트 1벌을 두고, 두 구현의 출력이 같은지 테스트로 확인한다.
- 각 후보의 기본 설정을 유지한다. temperature 같은 sampling 값은 지정하지 않는다.
- (후보, 과제)마다 3회 반복하고 성공 횟수와 중앙값을 보고한다.
- 각 후보는 문서가 권장하는 관용적 방식으로 구현한다. 기본 기능이 없으면 "없음"으로 기록하고, 우회 구현에 든 코드량을 잰다.

**관찰 포인트 (모델 호환성)**: 최신 Claude 모델(Opus 5.5, Sonnet 5.5)은 강제 `tool_choice`(any/tool)를 400으로 거부하고, Sonnet 5.5와 Haiku 5.5는 기본값이 아닌 sampling 값을 거부한다. 구조화 출력을 강제 도구 호출로 구현한 프레임워크는 실패할 수 있다. 이런 실패도 결과로 기록한다.

## 4. 과제 도메인: 건설 현장 이슈 관리 (mock)

실제 Cupix 데이터는 쓰지 않는다. 가상 현장 하나를 만든다.

- `issues.json`: 이슈 약 30건 (층, 구역, 공종, 상태, 심각도, 담당자, 생성일)
- `progress.csv`: 층 × 공종별 계획·실적 공정률
- `crew.json`: 공종별 작업자와 현재 배정 건수

공통 도구 5개: `search_issues`, `get_issue`, `get_progress`, `list_crew`, `assign_issue`(부수효과가 있으며 F3에서 승인 필요).
정답은 데이터에서 코드로 계산하고 채점은 자동화한다.

## 8. 실행 환경과 안전

- **Framework 트랙**: 호스트에서 uv와 pnpm으로 실행한다. 에이전트가 호출하는 것은 우리가 만든 mock 도구뿐이다.
- **Harness 트랙**: 하네스는 셸과 파일을 직접 다루므로 후보별 Docker 컨테이너(OrbStack)에서 실행한다. 작업 폴더 복사본만 마운트한다.
- **LLM 호출**: 모든 호출이 로컬 프록시(127.0.0.1)를 거쳐 OpenRouter로 간다. 키는 프록시만 갖고(keygate로 주입) 후보 코드와 컨테이너에는 가짜 키만 넣는다. 프록시는 필요한 엔드포인트만 전달하고, 누적 비용이 상한을 넘으면 요청을 막는다.

## 11. 한계 (발표 때 함께 밝힌다)

- 3회 반복은 작은 표본이다. 경향을 보는 용도로만 쓴다.
- mock 과제 6개가 실제 업무 전체를 대표하지는 않는다.
- 결과는 선택한 모델과 버전에 따라 달라진다. 기본 설정끼리의 비교이므로 튜닝 후 성능과 다를 수 있다.
- 같은 모델이어도 후보마다 OpenRouter 연동 방식(OpenAI 호환, Anthropic 호환, LiteLLM 경유)이 다르다. 그 차이도 결과에 포함된다.
